# AI 전쟁 시뮬레이터 — 리브랜딩 및 게임·오디오 설계

상태: 한국어 표시명 변경 구현, 아래 신규 메커니즘은 제안이며 미구현.
내부 프로젝트/세계관 브랜드 Tokenfront, 패키지 com.toris.tokenfront.tokenfront 및 세이브 식별자는 유지한다. 다른 언어 제목은 이번 변경 범위에서 유지한다. Play Console 제목은 별도 제출 전까지 기존 값이다.

## 제품 약속
자율 코어들의 전투를 관찰하고, 플레이어가 목적지를 선택해 결과를 바꾸는 전략 시뮬레이션. 생성형 AI 대화·실제 전쟁 예측·온라인 대전을 약속하지 않는다. 범용 제목의 검색 이해도는 가설이며 노출/전환 향상을 보장하지 않는다.

## 설계 기둥
1. 관찰 가능한 원인과 결과: 명령의 목표와 결과를 같은 화면에서 연결한다.
2. 짧고 의미 있는 개입: 기존 목적지 선택 회수 조작을 유지한다.
3. 실패해도 다음 실험: 스토리와 에코 주기 기록을 보존한다.
4. 공정한 경제: 유료 광고 제거는 전투 능력과 무관하며 보상 광고는 선택형이다.

## 현재 구현과 변경하지 않는 기준
스토리 5개 작전, 결말 이후 Echo Cycle, 노드 점유 8초/중간 피드백 5초, 좌우 HUD가 존재한다. 이름 변경을 이유로 검증된 시간·유닛 수·경제를 변경하지 않는다. 서로 다른 모드의 유닛 수를 하나의 스토어 문구로 단정하지 않는다.

## 핵심 루프와 종이 프로토타입
- 순간: 전황 확인 → 목적지 선택 → 이동/점유 관찰 → 다음 목표 판단.
- 세션: 작전 목표 확인 → 회수/실패 → 결과와 기록 확인 → 다음 작전 또는 재도전.
- 장기: 다섯 작전과 결말 → 기록을 유지한 에코 주기 → 최선 기록 개선.
- 종이 실험: 같은 시작 상태에 대해 목표 A/B를 선택한 두 경로를 나란히 그린다. 플레이어가 왜 결과가 달라졌는지 설명할 수 있는지 관찰한다. 엔진 실행 결과로 가장하지 않는다.

## 다음 구현 후보: 전술 결과 요약
목적: AI 전투에서 플레이어 개입의 의미를 전달한다.
입력: 실제 경기 이벤트(목적지 선택, 회수 완료, 종료 사유).
출력: 결과 화면에 선택한 경로·회수 순서·완료/실패 이유를 표시한다.
성공: 플레이테스터가 자신의 선택과 결과를 연결해 설명한다.
실패: 데이터에 없는 인과를 추정하거나 과장한 승리 기여도를 표시한다.
경계: 명령 없이 종료, 동시 회수, 재플레이, 앱 중단은 각각 실제 로그 상태를 표시한다. 가짜 AI 해설을 생성하지 않는다.
범위: 기존 기록으로 가능한 항목부터 구현; 새 이벤트 저장은 스키마/마이그레이션 테스트 후 진행.

## 오디오 방향 및 현재 코드 근거
소닉 정체성: 전자적·명료한·절제된.
현재 lib/services/audio/game_audio_service.dart는 dash, combatImpact, commandRelay, recoveryComplete 이벤트를 처리하며 마지막 두 이벤트는 relay.wav를 공유한다. combatThrottle은 150ms다. 기존 Flame 기반 이벤트 서비스와 중단/음소거 경계를 유지한다. 이번 제목 변경에 FMOD/Wwise 신규 도입은 포함하지 않는다.

### 제안 이벤트 분리 (미구현)
|상태|정보|우선순위/중복 정책|
|목적지 선택|명령 접수|높음, 연속 선택은 최신 1개|
|점유 중간|진행 유지|중간, 노드별 1회|
|회수 완료|목표 달성|높음, 중간 큐보다 우선|
|경기 결과|성공/실패|높음, 결과 진입 1회|

새 샘플은 직접 제작하거나 라이선스 확인 후 추가한다. 음악을 추가한다면 저강도 기본층과 전황 상승 상태를 구분하고 전환은 박자 경계에 맞춘다. 아직 음악 에셋 제작이나 적응형 음악 구현은 완료하지 않았다.

### 예산·튜닝 가설
|변수|기준/가설|검증|
|회수 시간|기존 8초 유지|회귀 테스트|
|중간 알림|기존 5초 유지|노드별 중복 방지|
|전투 타격 간격|기존 150ms 유지|밀집 전투에서 연타 피로 확인|
|새 SFX 동시 발성|최대 4 [PLACEHOLDER]|저사양 실기에서 드롭/클리핑 측정|
|음악 스트림|최대 1 [PLACEHOLDER]|광고·백그라운드·재개 전환 측정|

오디오를 꺼도 진행 호/텍스트로 같은 중요 정보를 제공한다. 전면 광고·일시정지·앱 백그라운드 중 재생 금지와 복귀 시 중복 재생 방지를 수락 기준으로 삼는다. 실기에서 측정하지 않은 CPU/메모리 예산을 달성했다고 보고하지 않는다.

## 모바일 구현 순서 및 수락 기준
1. 한국어 ARB appTitle, Android values-ko 앱 이름, 한국어 스토어 초안 정합성 확인.
2. 패키지·서명·세이브 키 불변, 나머지 로케일 유지, 제목 줄바꿈/접근성 실기 확인.
3. 결과 요약/오디오 이벤트 분리는 별도 기능 변경으로 테스트 후 구현.
4. 결제 비활성 빌드의 패치노트에 구매 가능하다고 표시하지 않는다.
5. AAB는 제목 반영한 정확한 커밋/서명/버전으로 검증하고, Play 제목 저장·게시 결과와 구분해서 보고한다.

## 플레이테스트 질문
- 첫 경기에서 무엇을 선택할 수 있는지 설명할 수 있는가?
- 승패 원인을 게임이 제시한 사실로 설명할 수 있는가?
- 명령 접수와 목표 달성 소리를 구별하는가?
- 음소거와 폴더블 화면에서도 목표와 다음 행동이 읽히는가?

수치 목표·새 경제 보상은 관찰 이후 정한다. 이번 문서는 검증 계획이지 플레이테스트 성공 보고가 아니다.
